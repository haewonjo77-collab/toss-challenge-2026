# 우선순위 1~7 반영 — 설계 문서

날짜: 2026-07-05
대상: 라우팅 연결된 앱에 대한 7가지 개선 요청. 애매한 지점은 SPEC/DESIGN 원칙으로 자율 판단,
근거를 여기 남긴다.

## P1 — 회의 시간 선택 (30분/1시간/1시간 30분/2시간)

- 네이티브 `<select>`를 text-input 토큰으로 스타일링 — "익숙한 패턴 재사용" 원칙상 커스텀
  피커를 만들지 않음. 기본값 1시간.
- duration이 상태로 전파되도록: MeetingContext에 `durationMinutes` 저장, 추천 슬롯의
  시간 라벨("화요일 오후 2:00 - 3:00")을 시작시각+duration에서 **생성**하도록
  `src/data/time.ts` 헬퍼 추가 (기존엔 1시간 고정 문자열). 화면 ④ 요약("· 1시간")도 선택값 반영.
- 참고: SPEC.md는 "시간 1시간(고정)"이라 명시 — 사용자 지시로 스펙이 변경된 것이므로 구현이
  우선하며, SPEC.md 원문 갱신은 별도 확인 사항으로 남긴다.

## P2 — 추천 결과 대안 후보

- 후보 슬롯을 2개→4개로 확장 (`recommendation.ts`). 정렬 1위가 메인 카드, 나머지 3개가
  "다른 시간 보기" 접힘 리스트. 기본 태그 기준: 메인 화요일(필수 4/4·선택 1/3), 대안
  금요일(4/4·0/3)·수요일(3/4·2/3)·목요일(3/4·1/3) — 필수/선택 조합이 서로 다른 트레이드오프.
- 대안 행 클릭 = 즉시 확정 (DESIGN.md Do: "추천 카드는 클릭 시 즉시 확정, 재확인 모달 없음").
  행에는 시간 + "필수 n/m · 선택 n/m" 카운트를 그레이스케일로 — 판단 정보만 제공, accent는
  여전히 메인 CTA 1개.

## P3 — 뒤로가기

- 프레임 상단에 고정 높이 BackBar(← 텍스트 버튼, 그레이스케일), `/`에서는 화살표 숨김
  (높이는 유지해 화면 전환 시 카드 위치가 안 튀도록). `navigate(-1)` — 라우트 히스토리 기준.
- 부수 수정: ②→①로 돌아가면 기존엔 CreateMeeting이 초기 mock으로 리셋되어 편집이 유실됨.
  CreateMeeting에 initialTitle/initialAttendees/initialDuration props를 추가해 컨텍스트
  값으로 시드 — 뒤로가서 태그를 바꾸는 것(CASE1↔CASE2 시연 경로)이 실제로 동작해야 하므로.

## P4 — 화면 ④ 차별화

- 상단에 44px 원형 체크(✓) 추가. **accent를 CTA에서 체크 마커로 이동**: 공유 버튼이
  secondary로 내려가면 화면에 accent가 0곳이 되는데, DESIGN.md는 accent 용도로 "선택된
  상태, 진행 표시"를 허용하므로 확정 완료 상태 마커가 화면당 1군데 accent 역할을 맡는 게
  원칙에 부합. 커스텀 아이콘 세트가 아닌 단일 ✓ 글리프(●○◐와 같은 접근).
- "참석자에게 공유하기" → button--secondary.

## P5 — 부서/팀 선택 입력

- `InvitedAttendee.team?: string`. 추가 폼: [이름][부서/팀 (선택)][추가] 한 줄, 비워도 추가 가능.
- 행 표시: 이름 아래 팀을 caption/muted로 스택 (361px 폭에서 토글·제거 버튼과 공존).
- 두 입력 모두 Enter 추가 + IME isComposing 가드 동일 적용.

## P6 — 참석자 보조 플로우 (가설 B)

- 라우트: `/join`(이름 입력) → `/join/times`(안 되는 시간) → `/join/done`(응답 요약).
  상태는 별도 `JoinContext`(이름, 안되는 슬롯, 제출 여부).
- **단계적 노출**: 월~금 5일을 [월·화·수] → [목·금] 2단계로 분할 (SPEC "며칠씩 나눠서 노출").
  주말은 업무 회의 맥락상 제외. 단계 표시 "1/2 단계" + 이전/다음(마지막 단계는 제출하기).
- **슬롯 단위 = 화면 ①의 회의 시간 길이**: 09:00~18:00을 duration 간격으로 생성
  (60분이면 9칸, 30분이면 18칸). 셀 토글 = 안되는 시간만 음영(surface-strong) —
  DESIGN.md calendar-cell 토큰 그대로, 표준 그리드 패턴 (`TimeGrid.tsx` 신규).
- 응답 요약: WaitingRoom의 행 리스트를 `ResponseList.tsx`로 추출해 양쪽에서 재사용.
  mock 로스터는 초대 링크 단독 접속 시나리오이므로 주최자 세션 상태와 분리 —
  기본 7명 중 마지막 2명 미응답 규칙 재사용, 입력한 이름이 로스터에 있으면 그 사람을
  응답완료로, 없으면 새 응답자로 추가.
- 진입점: 목업에서 도달 가능해야 하므로 화면 ②(대기) 카드 아래에
  "참석자 응답 화면 미리보기 →" 텍스트 링크(muted) 추가 — 주최자 UI를 해치지 않는 최소 노출.

## P7 — 최근 참석자 빠른 추가

- `recentAttendees` mock(이름+팀)을 이름 입력 필드 위 "최근 참석자" 칩(pill, 그레이스케일)으로
  노출. 클릭 시 '선택' 역할로 즉시 추가(필수 승격은 의도적 행위 원칙 유지), 이미 목록에 있는
  이름은 칩에서 숨김. localStorage 미사용 — 정적 mock으로 개념만 시연 (SPEC "범위 밖"이던
  항목을 사용자 지시로 최소 형태 반영).

## 커밋 단위

P1~P7 각각 빌드(tsc 포함) 통과 후 개별 커밋. P6은 ResponseList 추출 리팩터링 포함.
