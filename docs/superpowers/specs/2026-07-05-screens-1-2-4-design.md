# 화면 ①(회의 만들기) · ②(대기) · ④(확정) — 설계 문서

날짜: 2026-07-05
대상: SPEC.md 메인 플로우의 나머지 세 화면. 화면 ③(추천 결과 확인)에서 확정된 패턴
(카드 구조, 그레이스케일 + accent 1군데, ●/○/◐ 형태 구분, CSS 변수 토큰)을 그대로 잇는다.
사용자 지시에 따라 애매한 지점은 SPEC/DESIGN 원칙 기준으로 자율 판단하고, 판단 근거를
이 문서에 남긴다.

## 공통 원칙 (화면 ③에서 계승)

- 카드: canvas 배경 + hairline 보더 + radius-lg(12px) + padding lg, max-width 361px
- accent는 화면(카드)당 주요 CTA 버튼 1개에만
- 정보 구분은 색이 아니라 텍스트·형태로
- 컴포넌트는 독립 단위로 만들고 `App.tsx`는 쇼케이스로 나란히 렌더링
- mock 인물은 화면 ③과 동일한 7명(김도윤·박서연·이준호·최민아 / 정하늘·강지훈·오예린)을
  재사용해 화면 간 연속성 유지 (SPEC의 "6인" 표기와 다르지만, 이미 승인된 화면 ③ 데이터와의
  일관성을 우선)

## 화면 ① 회의 만들기 — CreateMeeting

구성 (위→아래):
1. 화면 제목 "회의 만들기" (title-lg)
2. 회의 제목 입력 — DESIGN.md `text-input` 토큰 (44px, hairline 보더, 포커스 시 ink 보더)
3. 회의 시간 — "1시간" 읽기 전용 표시 + 캡션 "회의 시간은 1시간으로 고정돼요"
   (SPEC: 시간 1시간 고정이므로 입력이 아니라 상태 표시)
4. 참석자 리스트 — Avatar + 이름 + **필수/선택 세그먼트 토글** + 제거(×) 버튼
5. 참석자 추가 — 이름 입력 + "추가" 버튼(secondary)
6. CTA "초대 링크 보내기" (primary accent, 제목 미입력 시 disabled)

**판단 1 — 필수/선택 태그 UI: 세그먼트 토글(pill 2분할)**
- 후보: 드롭다운(2개 옵션에 과함, 탭 수 +1), 스와이프(발견 가능성 낮고 목업에서 검증 불가),
  체크박스("필수 여부" 부정형 라벨이 됨), 세그먼트 토글.
- 세그먼트 컨트롤은 iOS/토스 계열 앱에서 가장 익숙한 2택 패턴이고, DESIGN.md pill 토큰과
  배지 형태(필수=굵게)를 그대로 재사용할 수 있어 "익숙한 패턴 재사용, 새로 발명하지 않기"
  원칙에 가장 부합. 선택된 세그먼트는 canvas 배경 + hairline 보더 + ink(필수는 700 굵기),
  비선택은 muted — 그레이스케일 유지, accent 미사용.
- 새로 추가되는 참석자의 기본값은 '선택' — 필수 지정은 주최자의 의도적 행위여야 추천
  로직(가설 C)의 신뢰도가 유지되므로 보수적 기본값을 택함.

## 화면 ② 대기 화면 — WaitingRoom

구성:
1. 헤드라인 "7명 중 5명 응답완료" (title-lg — SPEC ②의 현황판 핵심 정보)
2. 상태 안내문 (body-sm): 미완료 시 "2명이 응답하면 추천 시간을 볼 수 있어요",
   완료 시 "모든 참석자가 응답했어요"
3. 참석자 리스트 — Avatar + 이름 + 응답 상태 텍스트("응답완료" ink / "대기중" muted).
   SPEC ② "이름·응답여부만 표시"에 따라 필수/선택 태그·응답시각은 표시하지 않음.
   ●/○ 아이콘은 화면 ③에서 "참석 가능 여부"의 의미로 이미 쓰이므로, 의미 충돌을 피해
   응답 여부는 텍스트로만 구분.
4. CTA "추천 시간 보기" (primary) — 전원 응답 전에는 disabled(accent-disabled 배경)

**판단 2 — "전원 응답 완료해야 화면 ③ 진입": 버튼 비활성화 + 안내 문구 둘 다**
- 닐슨 휴리스틱 "시스템 상태의 가시성" 기준: disabled 버튼만으로는 *왜* 안 되는지와
  *언제* 가능해지는지를 알 수 없고, 문구만으로는 액션 가능 여부가 즉시 드러나지 않음.
- 그래서 3중 표현: (a) 헤드라인 카운트 "7명 중 5명"으로 진행도, (b) 안내문으로 남은 조건
  ("2명이 응답하면…"), (c) disabled 버튼으로 현재 액션 불가 상태. 전원 응답 시 안내문이
  완료 확인으로 바뀌고 버튼이 활성화되어 상태 변화가 세 층위에서 일관되게 보임.
- App.tsx에는 진행 중(5/7)과 완료(7/7) 두 상태를 나란히 렌더링해 비교 검증.

## 화면 ④ 확정 — ConfirmedMeeting

SPEC ④: 후보 클릭 → 즉시 확정(재확인 없음). 따라서 이 화면은 "확정 직후 결과 상태" 화면.

구성:
1. "회의가 확정되었어요" (title-md) — 확정 사실을 먼저
2. 확정 시간 (title-lg) — 화면 ③과 동일한 위계로 시간이 가장 큰 정보
3. 회의 제목·시간 요약 캡션 "주간 제품 리뷰 · 1시간" (body-sm muted)
4. 필수/선택 배지 + 참석자 섹션(●/○/◐) — 화면 ③의 Badge/AttendeeRow 재사용,
   확정된 시간 기준의 참석 현황을 그대로 보여줌 (CASE 1 데이터 재사용: 필수 4/4, 선택 2/3)
5. CTA "참석자에게 공유하기" (primary accent 1개) — 확정 후 자연스러운 다음 행동
